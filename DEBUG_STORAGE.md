# 🔍 Отладка: Данные теряются при очистке истории

## Проблема

При очистке истории браузера в Linux Mint через VSCode Live Server приложение начинается с начала (все данные теряются).

## Ожидаемое поведение ✅

Это **нормально**, когда вы:
- Выбираете "Очистить историю" → ставите галочку "Файлы куки и другие данные сайтов"
- Браузер удаляет ВСЕ хранилища одновременно (localStorage, IndexedDB, кэш)

## Что удаляется при очистке истории

Когда вы очищаете историю в браузере, он удаляет:

✅ **Удаляется:**
- 📍 localStorage
- 📍 IndexedDB  
- 📍 sessionStorage
- 📍 Cookies
- 📍 Service Worker кэш
- 📍 Разрешения и настройки сайта

❌ **НЕ удаляется:**
- 📁 Система файлов приложения (HTML, CSS, JS)
- 📱 Service Worker сам по себе

## Решения

### 1. При очистке истории НЕ удаляйте данные сайтов

**Chrome/Chromium:**
- History → Clear browsing data
- "Time range" → выбрать нужный период
- ❌ СНЯТЬ галочку "Cookies and other site data"
- ✅ Оставить включенным "Cached images and files"

**Firefox:**
- History → Clear Recent History
- "Time range to clear" → выбрать нужный период
- ❌ СНЯТЬ галочку "Cookies" и "Site data"

**Safari:**
- Safari → Clear History
- "Clear:" → выбрать период
- ✅ Это удалит только историю, не трогая данные

### 2. Разрешить постоянное хранилище

При первом открытии приложения браузер может спросить разрешение. Нажмите "Разрешить":

```
"Мій цикл" хочет использовать ваше дисковое пространство для хранения данных приложения?
[Отклонить] [Разрешить]
```

Выберите "Разрешить" (но это не полная защита — при ручной очистке все равно удалится).

### 3. Добавить приложение на главный экран (рекомендуется)

Браузер обычно автоматически активирует постоянное хранилище для PWA на главном экране:

**iOS:**
- Откройте приложение в Safari
- Нажмите Поделиться (Share)
- "Add to Home Screen"
- ✅ Данные будут лучше защищены

**Android:**
- Откройте приложение в Chrome
- Нажмите Меню (⋮)
- "Install app" или "Add to Home screen"
- ✅ Данные будут лучше защищены

## Диагностика

Если вы хотите проверить, сохраняются ли данные:

### Шаг 1: Открыть консоль браузера

```
F12 → Console (или Ctrl+Shift+K)
```

### Шаг 2: Вставить и выполнить диагностику

Скопируйте в консоль:

```javascript
// Проверить localStorage
console.log("localStorage cycleData:", localStorage.getItem("cycleData"));
console.log("localStorage cycleMarks:", localStorage.getItem("cycleMarks"));

// Проверить StorageManager
StorageManager.get("cycleData").then(data => {
  console.log("StorageManager cycleData:", data);
});

StorageManager.get("cycleMarks").then(data => {
  console.log("StorageManager cycleMarks:", data);
});

// Проверить IndexedDB
navigator.storage.estimate().then(estimate => {
  console.log("IndexedDB используется:", (estimate.usage / 1024 / 1024).toFixed(2), "МБ");
  console.log("IndexedDB доступно:", (estimate.quota / 1024 / 1024).toFixed(2), "МБ");
});

// Проверить постоянное хранилище
navigator.storage.persisted().then(persistent => {
  console.log("Постоянное хранилище:", persistent ? "✅ Да" : "❌ Нет");
});
```

### Шаг 3: Полная диагностика

Если хотите полный отчет, выполните:

```javascript
diagnosis();
```

Это выведет подробный отчет обо всех хранилищах, IndexedDB, Storage API и состоянии приложения.

## Шаги для тестирования при разработке

### ✅ Правильный способ

```
1. Откройте приложение в браузере
2. Введите данные (начните цикл)
3. Перезагрузите страницу (F5)
   → Данные должны сохраниться ✅
4. Закройте вкладку и откройте заново
   → Данные должны сохраниться ✅
5. Откройте DevTools → Application → Storage
   → Проверьте localStorage и IndexedDB ✅
```

### ❌ Как потерять данные (ожидаемо)

```
1. Откройте приложение в браузере
2. Введите данные
3. History → Clear browsing data
4. Поставьте галочку "Cookies and other site data"
5. Clear browsing data
   → Данные удалены ✅ (это ожидаемо)
```

## Для локального тестирования (Live Server)

На локальном хосте (localhost:5500 или аналог) работает все хранилище:

✅ **Работает корректно:**
- localStorage сохраняется
- IndexedDB сохраняется
- sessionStorage работает
- Cookies сохраняются

❌ **Потеря данных только при:**
- Очистке "Cookies and other site data"
- Удалении БД вручную
- Очистке кэша браузера со сбросом данных

## Проверка логов инициализации

При загрузке страницы откройте консоль (F12 → Console):

### ✅ Успешная инициализация должна показать:

```

✅ localStorage работает (основное хранилище)
✅ IndexedDB инициализирована (дополнительное хранилище)
✓ Постоянное хранилище активировано...
📊 Статус хранилища: Постоянное 🔒
✅ Система хранения готова
📦 Данные загружены из localStorage (cycleData)
📦 Данные загружены из localStorage (cycleMarks)
✓ Данные приложения загружены
```

### ⚠️ Если видите ошибки:

```
❌ localStorage недоступен: ...
❌ IndexedDB не работает: ...
```

**Решение:** 
- Проверьте, не включен ли приватный режим браузера
- Убедитесь, что браузер позволяет хранилище для localhost
- Перезагрузите браузер
- Попробуйте другой браузер

## FAQ

**В: Почему данные удаляются при очистке истории?**  
О: Это встроенное поведение браузера для защиты приватности. Все веб-хранилища удаляются вместе с историей.

**В: Как защитить данные от очистки?**  
О: Не выбирайте "Файлы куки и другие данные сайтов" при очистке истории.

**В: Работает ли на мобильных устройствах?**  
О: Да, и даже лучше. Добавьте приложение на главный экран для максимальной защиты.

**В: Могу ли я экспортировать данные?**  
О: Да, добавьте функцию экспорта в JSON и импорта. Это поможет пользователям сделать бэкап.

**В: А если браузер используется приватный режим?**  
О: В приватном режиме все хранилища очищаются при закрытии вкладки. Используйте обычный режим.
